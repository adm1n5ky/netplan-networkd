# netplan-networkd

Набор скриптов для безопасного перевода **Ubuntu Server 26.04** с управления сетью через `NetworkManager` на связку `netplan` + `systemd-networkd` без потери SSH-доступа.

## Зачем это нужно

Многие облачные провайдеры развертывают образы Ubuntu Server с активным `NetworkManager` или нестандартной маршрутизацией (например, IPv4 с маской `/32` и шлюзом вне подсети, а также link-local шлюзами IPv6 `fe80::1`).

Скрипты автоматически снимают рабочие параметры сети с живого сервера, формируют корректный YAML-конфиг и выполняют безопасное переключение с возможностью автоматического отката.

## Состав репозитория

* **`migrate.sh`** — основной входной скрипт для проверки ОС, сбора сетевых параметров, генерации образца конфигурации и запуска миграции.
* **`apply.sh`** — скрипт безопасного применения конфигурации, создания бэкапов и отключения `NetworkManager`.
* **`netplan-collect.sh`** — автономная утилита для сбора текущих сетевых параметров и генерации шаблона YAML без интерактивного меню.

## Как это работает

Процесс миграции разделен на два этапа:

1. **Сбор и диагностика (`migrate.sh`):**
   * Проверяет, что система является чистой **Ubuntu Server 26.04** без графического окружения (`ubuntu-desktop`, `gdm`).
   * Определяет текущий активный сетевой менеджер.
   * Собирает интерфейс по умолчанию, глобальные IPv4/IPv6-адреса, шлюзы и актуальные DNS-серверы (с интерфейса и из `Global`).
   * Учитывает особенности маршрутизации: добавляет `on-link: true` для IPv4-шлюзов и исключает его для link-local адресов IPv6 (`fe80::`).
   * Сохраняет готовый образец конфигурации в `./netplan-sample.yaml` и предлагает интерактивный выбор: выйти для ручной проверки или сразу перейти ко второму этапу.

2. **Безопасное применение (`apply.sh`):**
   * Создает резервную копию всех текущих файлов `/etc/netplan/*.yaml` в `/root/netplan-backup-ДАТА/` и отключает старые конфиги (`.bak`).
   * Копирует новый конфиг в `/etc/netplan/01-netcfg.yaml` (базовый слой, поверх которого можно добавлять кастомные конфиги, например для туннелей Hurricane Electric) и выставляет права `600`.
   * Валидирует синтаксис через `netplan generate`.
   * Запускает `systemd-networkd` **до** остановки `NetworkManager`.
   * Применяет настройки через `netplan try --timeout 120` — если связь пропадет, конфигурация автоматически откатится через 2 минуты.
   * Проверяет доступность шлюза по умолчанию и только после этого останавливает и маскирует `NetworkManager`.

## Быстрый старт

Выполните на сервере от имени `root` (или через `sudo`):

```bash
curl -fsSL https://githubusercontent.com | sudo bash
```

После вывода диагностики и сгенерированного файла `./netplan-sample.yaml` скрипт предложит выбрать действие:
* Нажмите **`1`** — чтобы выйти без изменения настроек сети и изучить сгенерированный `./netplan-sample.yaml` вручную.
* Нажмите **`2`** — чтобы запустить `apply.sh` и перевести сеть на `systemd-networkd`.

### Ручной запуск второго этапа

Если вы выбрали `1`, проверили `./netplan-sample.yaml` (или отредактировали его под свои нужды) и готовы применить настройки:

```bash
curl -fsSL https://githubusercontent.com | sudo bash
```

## Откат изменений

Если потребуется вернуть предыдущую конфигурацию:

1. Восстановите файлы из резервной копии (точный путь выводится в конце работы `apply.sh`):
   ```bash
   rm -f /etc/netplan/01-netcfg.yaml
   cp /root/netplan-backup-*/*.yaml /etc/netplan/
   ```
2. Размаскируйте и запустите `NetworkManager`:
   ```bash
   systemctl unmask NetworkManager
   systemctl enable --now NetworkManager
   netplan apply
   ```
